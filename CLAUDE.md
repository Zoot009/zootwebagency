# Zoot Web Agency: WordPress → Next.js migration

We are rebuilding https://powderblue-gaur-774652.hostingersite.com (WordPress + Elementor + Rank Math)
in Next 16. URLs, content and SEO must be IDENTICAL to the live site. The design must match visually.
Four people work in parallel, each owning one page *family* (see Ownership).

## How pages work (read before touching anything)
- Every page's content + SEO lives in `content/pages/*.json`, generated by `npm run import`
  (`scripts/import-wp.mjs`). WP pages that redirect live in `content/redirects.json` → `next.config.ts`.
- ONE route renders every URL, including the homepage: `app/[[...slug]]/page.tsx`.
  It picks a template by the JSON's `family` field: `home | service | cityHub | cityService | article | generic`.
- `lib/content.ts`: `getAllPages()`, `getPage(slug)`, `toMetadata(page)` (Rank Math tags → Next Metadata).
- Templates: `components/templates/<Family>.tsx`. Each starts as a stub that renders `GenericPage`
  (the raw Elementor HTML). Shared blocks (hero, FAQ, CTA, …) go in `components/sections/`.
- NEVER create a per-page route like `app/seo-services/page.tsx`. If a page looks wrong, fix its family
  template or the importer, so every page in that family is fixed together.

## Hard rules
1. Do not hand-edit `content/pages/*.json` or `content/redirects.json`. Change `scripts/import-wp.mjs`
   and re-run `npm run import`. Content edits happen in WordPress until cutover.
2. Do not write or change SEO by hand: title, description, robots, canonical, OG/Twitter, and JSON-LD
   all come from the JSON via `generateMetadata` + `toMetadata`. Never add a `metadata` export elsewhere.
   Templates must not render their own `<title>`, `<meta>`, or `application/ld+json`.
3. Do not rewrite, "improve", summarize, or shorten copy. Text must match WordPress word for word.
   Keep heading levels exactly as on the live page (one h1 per page). Keep link targets and anchor text.
4. Never rename slugs or change URLs. Trailing slashes stay (`trailingSlash: true`).
5. Images live in `public/uploads/…` (mirrors `wp-content/uploads`). Use them via `next/image` with
   the original alt text. Never hotlink the WordPress host: it will be shut down.
6. Styling: Tailwind only. No new CSS frameworks, UI kits, or Elementor CSS. Colors/fonts are tokens in
   `app/globals.css` (`@theme`). Reuse them; don't invent new hex values. Mobile-first.
7. No new npm dependencies without team agreement.
8. Only edit files in YOUR family, plus new files in `components/sections/`. To change `lib/`, `app/`,
   `scripts/`, `next.config.ts`, or another family's template, agree with the owner first (one small PR).
9. Server components by default. Add `"use client"` only for real interactivity (menu, accordion, form),
   and keep that component small.
10. Next 16 differs from your training data. Read `node_modules/next/dist/docs/` before using a Next API.

## Building a template
1. Open 2–3 live pages of your family and their JSON files. Find the repeated sections.
2. Pull content into the template from `page.html`: either parse it in the template, or (better, for
   structured sections) add a family-specific extractor in `scripts/import-wp.mjs` that writes extra
   fields to the JSON, then `npm run import`. Add any new field to the `Page` type in `lib/content.ts`.
3. Match the live design at 375px, 768px, and 1280px. Compare side by side with the WP page.
4. Click through EVERY page of the family, not just the samples. Elementor pages vary; anything a page
   has that the template doesn't must still render (fall back to the raw HTML for that section).

## Before every push
```
npm run lint && npm run build
npm start                                   # in another terminal
npm run check-seo -- --family <family>      # must print N/N pages match
```
Branch `family/<name>`, small PRs, one reviewer from the team. Never commit `.next/`.

## Done means
Visual match on desktop and mobile, `check-seo` all green, build and lint pass, no console errors,
and no request to the WordPress host in the browser network tab.
